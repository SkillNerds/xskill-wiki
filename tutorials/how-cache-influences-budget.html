How Cache Influences Your Budget

The three-part cost formula for multi-turn agent sessions — and an interactive calculator to see the numbers yourself.

The Cost Formula

For an agent session with $n$ turns, the total cost $P_n$ decomposes into three terms:

$$P_n = \underbrace{P_{cr}(S_0+U_0)n + P_{cr}\sum_{i=1}^{n}(n-i)(R_i+C_i+T_i+TR_i+U_i)}_{\text{Cache Read}} + \underbrace{P_i(S_0+U_0) + P_i\sum_{i=1}^{n}(TR_i+U_i)}_{\text{Uncached Input}} + \underbrace{P_o\sum_{i=1}^{n}(R_i+C_i+T_i)}_{\text{Output}}$$

Understanding the Three Terms

Term 1: Cache Read

The system prompt $S_0 + U_0$ is read $n$ times as a prefix — it appears at the start of every request. Turn $i$'s block (reasoning $R_i$, content $C_i$, tool calls $T_i$, tool results $TR_i$, user message $U_i$) is reused $(n - i)$ times in subsequent turns. This captures the decay: early turns get reused many times, while the last turn's block is never reused. All of this is charged at the cache read price $P_{cr}$, which is much cheaper than the full input price.

Term 2: Uncached Input

Only the first occurrence of $S_0 + U_0$ and each turn's new user message $U_i$ plus tool result $TR_i$ are charged at the full input price $P_i$. These are tokens the model sees for the first time — they cannot come from cache.

Term 3: Output

Model-generated tokens — reasoning $R_i$, content $C_i$, and tool calls $T_i$ — are always charged at the output price $P_o$. Output tokens are never cached; the model produces them fresh each turn.

For Direct Chat mode, set $R$, $T$, and $TR$ to zero in the formula — those token types do not appear in simple chat interactions.

缓存如何影响你的预算

多轮 Agent 会话的三项成本公式，以及一个交互式计算器让你自己看数字。

成本公式

对于一个 $n$ 轮的 Agent 会话，总成本 $P_n$ 拆解为三项：

$$P_n = \underbrace{P_{cr}(S_0+U_0)n + P_{cr}\sum_{i=1}^{n}(n-i)(R_i+C_i+T_i+TR_i+U_i)}_{\text{Cache Read}} + \underbrace{P_i(S_0+U_0) + P_i\sum_{i=1}^{n}(TR_i+U_i)}_{\text{Uncached Input}} + \underbrace{P_o\sum_{i=1}^{n}(R_i+C_i+T_i)}_{\text{Output}}$$

理解三项的含义

第一项：缓存读取

系统提示 $S_0 + U_0$ 作为前缀被读取 $n$ 次——每次请求都在开头出现。第 $i$ 轮的块（推理 $R_i$、内容 $C_i$、工具调用 $T_i$、工具结果 $TR_i$、用户消息 $U_i$）在后续轮次中被重用 $(n - i)$ 次。这体现了衰减：早期轮次被大量复用，最后一轮的块则从不被复用。全部按缓存读取价 $P_{cr}$ 计费，远低于全价输入。

第二项：未缓存输入

只有 $S_0 + U_0$ 的首次出现，以及每轮新的用户消息 $U_i$ 加工具结果 $TR_i$，按全价输入 $P_i$ 计费。这些是模型第一次见到的 token，不可能来自缓存。

第三项：输出

模型生成的 token——推理 $R_i$、内容 $C_i$、工具调用 $T_i$——始终按输出价 $P_o$ 计费。输出 token 不会被缓存，模型每轮都重新生成。

直聊模式下，把公式中的 $R$、$T$、$TR$ 设为零即可——简单聊天交互不涉及这些 token 类型。
