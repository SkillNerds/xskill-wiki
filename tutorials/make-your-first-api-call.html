Make Your First API Call

Learn the two modes of talking to a reasoning model — Direct Chat and Agent mode — and understand why they handle reasoning_content differently.

1. Direct Chat: Ask a Question

Let's start with the simplest possible call. Install the OpenAI-compatible client and talk to DeepSeek's reasoning model:

pythonfrom openai import OpenAI client = OpenAI( api_key="<DeepSeek API Key>", base_url="https://api.deepseek.com" ) messages = [{"role": "user", "content": "9.11 and 9.8, which is greater?"}] response = client.chat.completions.create( model="deepseek-v4-pro", messages=messages, reasoning_effort="high", extra_body={"thinking": {"type": "enabled"}} ) # The response has TWO sibling fields: reasoning_content = response.choices[0].message.reasoning_content content = response.choices[0].message.content print("Thinking:", reasoning_content[:200]) print("Answer:", content)

Run this and you'll see two things come back:

  • reasoning_content — the model's internal chain-of-thought (the "thinking")
  • content — the final answer shown to the user

Multi-turn: What happens to reasoning_content?

Now let's add a second turn. Watch what we do with the assistant message:

python# Turn 2 — append the assistant response, then ask again messages.append(response.choices[0].message) messages.append({'role': 'user', 'content': "How many Rs in 'strawberry'?"}) response2 = client.chat.completions.create( model="deepseek-v4-pro", messages=messages, reasoning_effort="high", extra_body={"thinking": {"type": "enabled"}} )
Key insight: Even though the assistant message in messages still contains reasoning_content, the API silently discards it. The server only looks at content when processing the history. This is Direct Chat mode — reasoning is ephemeral.

2. Agent Mode: Add Tools

Now let's turn this into an Agent. The only structural difference: we pass a tools parameter. But this changes the rules dramatically.

pythonimport json tools = [{ "type": "function", "function": { "name": "get_weather", "description": "Get current weather for a city", "parameters": { "type": "object", "properties": {"city": {"type": "string"}}, "required": ["city"] } } }] TOOL_CALL_MAP = { "get_weather": lambda city: json.dumps({"temp": "22°C", "condition": "sunny"}) } messages = [{"role": "user", "content": "What's the weather in Tokyo?"}] while True: response = client.chat.completions.create( model='deepseek-v4-pro', messages=messages, tools=tools, reasoning_effort="high", extra_body={"thinking": {"type": "enabled"}} ) # MUST include full message (with reasoning_content!) messages.append(response.choices[0].message) tool_calls = response.choices[0].message.tool_calls if tool_calls is None: break for tool in tool_calls: result = TOOL_CALL_MAP[tool.function.name]( **json.loads(tool.function.arguments) ) messages.append({ "role": "tool", "tool_call_id": tool.id, "content": result }) print(response.choices[0].message.content)
Critical difference: In Agent mode, reasoning_content MUST be passed back in subsequent turns. If you strip it, the server returns HTTP 400. The reasoning is no longer ephemeral — it's part of the conversation state.

3. Side-by-Side: Two Modes Compared

Here's pseudo-code showing how the message list is assembled differently in each mode:

Direct Chat Mode

# Server IGNORES reasoning_content messages = [ {role: system, content: S₀}, {role: user, content: U₀}, {role: assistant, content: C₁}, # ↑ reasoning_content silently dropped {role: user, content: U₁}, {role: assistant, content: C₂}, {role: user, content: U₂}, ... ]

Agent Mode (with tools)

# reasoning_content REQUIRED messages = [ {role: system, content: S₀}, {role: user, content: U₀}, {role: assistant, reasoning_content: R₁, content: C₁, tool_calls: [T₁]}, {role: tool, content: TR₁}, {role: assistant, reasoning_content: R₂, content: C₂}, {role: user, content: U₁}, ... ]

4. Symbol Notation

For the rest of this tutorial series, we use compact symbols to refer to each part of a multi-turn conversation:

SymbolMeaningAPI field
S₀System prompt{"role": "system", "content": ...}
U₀, U₁, …, UₙUser input at turn i{"role": "user", "content": ...}
RᵢReasoning (thinking) at turn imessage.reasoning_content
CᵢContent (final answer) at turn imessage.content
TᵢTool call(s) at turn imessage.tool_calls
TRᵢTool result at turn i{"role": "tool", "content": ...}
Why these symbols matter: In the next tutorials, we'll use them to write concise formulas for cache hit rate and cost. For example, the total input tokens at turn n in Agent mode is: S₀ + U₀ + Σ(Rᵢ + Cᵢ + Tᵢ + TRᵢ + Uᵢ) for i = 1..n.

Summary

  • A reasoning model returns two fields: reasoning_content (thinking) and content (answer).
  • In Direct Chat, reasoning is ephemeral — the server drops it from history.
  • In Agent mode (with tools), reasoning is mandatory — stripping it causes errors.
  • This structural difference is what makes Agent mode's cache behavior fundamentally different from Direct Chat, as we'll see next.

发出你的第一个 API 请求

学习与推理模型对话的两种模式 —— 直聊模式与 Agent 模式 —— 并理解它们为何以不同方式处理 reasoning_content。

1. 直聊模式：问一个问题

我们从最简单的调用开始。安装 OpenAI 兼容客户端，调用 DeepSeek 的推理模型：

pythonfrom openai import OpenAI client = OpenAI( api_key="<DeepSeek API Key>", base_url="https://api.deepseek.com" ) messages = [{"role": "user", "content": "9.11 and 9.8, which is greater?"}] response = client.chat.completions.create( model="deepseek-v4-pro", messages=messages, reasoning_effort="high", extra_body={"thinking": {"type": "enabled"}} ) # 返回中有两个并列字段： reasoning_content = response.choices[0].message.reasoning_content content = response.choices[0].message.content print("思考过程:", reasoning_content[:200]) print("最终回答:", content)

运行后你会看到两样东西：

  • reasoning_content — 模型内部的思维链（"思考过程"）
  • content — 给用户看的最终回答

多轮对话：reasoning_content 会怎样？

现在加一个第二轮。注意我们怎么处理 assistant 消息：

python# 第二轮 —— 把 assistant 回复追加进去，再问一个问题 messages.append(response.choices[0].message) messages.append({'role': 'user', 'content': "How many Rs in 'strawberry'?"}) response2 = client.chat.completions.create( model="deepseek-v4-pro", messages=messages, reasoning_effort="high", extra_body={"thinking": {"type": "enabled"}} )
关键认知：尽管 messages 里的 assistant 消息仍然带着 reasoning_content，API 会静默丢弃它。服务端在处理历史时只看 content。这就是直聊模式 —— 推理是临时的、用完即弃的。

2. Agent 模式：加入 Tools

现在把它变成 Agent。结构上唯一的区别：传入 tools 参数。但规则因此彻底改变。

pythonimport json tools = [{ "type": "function", "function": { "name": "get_weather", "description": "Get current weather for a city", "parameters": { "type": "object", "properties": {"city": {"type": "string"}}, "required": ["city"] } } }] TOOL_CALL_MAP = { "get_weather": lambda city: json.dumps({"temp": "22°C", "condition": "sunny"}) } messages = [{"role": "user", "content": "东京现在天气怎么样？"}] while True: response = client.chat.completions.create( model='deepseek-v4-pro', messages=messages, tools=tools, reasoning_effort="high", extra_body={"thinking": {"type": "enabled"}} ) # 必须保留完整的 message（包含 reasoning_content！） messages.append(response.choices[0].message) tool_calls = response.choices[0].message.tool_calls if tool_calls is None: break for tool in tool_calls: result = TOOL_CALL_MAP[tool.function.name]( **json.loads(tool.function.arguments) ) messages.append({ "role": "tool", "tool_call_id": tool.id, "content": result }) print(response.choices[0].message.content)
关键区别：在 Agent 模式下，reasoning_content 必须在后续轮次中传回。如果你把它去掉，服务端会返回 HTTP 400 错误。推理不再是临时的——它是对话状态的一部分。

3. 并排对比：两种模式的 messages 组装

以下伪代码展示两种模式下 message 列表的不同组装方式：

直聊模式

# 服务端会忽略 reasoning_content messages = [ {role: system, content: S₀}, {role: user, content: U₀}, {role: assistant, content: C₁}, # ↑ reasoning_content 被静默丢弃 {role: user, content: U₁}, {role: assistant, content: C₂}, {role: user, content: U₂}, ... ]

Agent 模式（带 tools）

# reasoning_content 必须保留 messages = [ {role: system, content: S₀}, {role: user, content: U₀}, {role: assistant, reasoning_content: R₁, content: C₁, tool_calls: [T₁]}, {role: tool, content: TR₁}, {role: assistant, reasoning_content: R₂, content: C₂}, {role: user, content: U₁}, ... ]

4. 符号记法

在后续教程中，我们用以下紧凑符号来指代多轮对话的各个组成部分：

符号含义对应的 API 字段
S₀系统提示词{"role": "system", "content": ...}
U₀, U₁, …, Uₙ第 i 轮的用户输入{"role": "user", "content": ...}
Rᵢ第 i 轮的推理（思考）message.reasoning_content
Cᵢ第 i 轮的内容（最终回答）message.content
Tᵢ第 i 轮的工具调用message.tool_calls
TRᵢ第 i 轮的工具返回{"role": "tool", "content": ...}
为什么这些符号很重要：在接下来的教程中，我们会用它们写出缓存命中率和成本的简洁公式。例如，Agent 模式下第 n 轮的总输入 token 数为：S₀ + U₀ + Σ(Rᵢ + Cᵢ + Tᵢ + TRᵢ + Uᵢ)，其中 i = 1..n。

小结

  • 推理模型返回两个字段：reasoning_content（思考）和 content（回答）。
  • 直聊模式下，推理是临时的——服务端会从历史中丢弃它。
  • Agent 模式下（带 tools），推理是必须的——去掉会报错。
  • 这种结构差异使得 Agent 模式的缓存行为与直聊模式根本不同，下一篇我们就来讲这个。
